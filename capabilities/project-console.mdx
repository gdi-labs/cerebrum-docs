## The project list

`/projects` shows every project you can access as a card grid — status, repo,
branch, and last-edit timestamps at a glance. Create a new project or open one
into its console.

## The console

Each project lives at its own URL with its own command bar, board, sidebar,
and search:

- **One command bar carries every fact once.** Project identity, a single
  stat ribbon (`N workflows · C/T prompts`), repository link, the canonical
  **+ Workflow** action, and ⌘K. No repeated counts.
- **The who × what-kind mix is legible at a glance.** A contributor avatar
  stack plus active-kind chips (Build / QA / Research / Docs / Review), with
  running kinds pulsing. A focused single-author project collapses this to a
  quiet `Azat · Build`; a mixed project expands it — and the board auto-groups
  by kind.
- **The board fills space at 0 / 1 / many workflows.** Every workflow renders
  as a card answering who + what + state in one glance: kind tile, status
  pill, author avatar, prompt progress. Group the board by Kind, Author, or
  Status; one **Load more** advances everything together. A brand-new project
  gets the **Launchpad** — an inline composer instead of a lone button.
- **The sidebar** is a compact workflow rail (with its own status filter) over
  an **Activity strip**: an actor-led, verb-led feed — `Azat · Build ·
  completed · "…"` — of the project's recent state changes.
- **⌘K** opens a project-scoped palette: fuzzy search over objectives and
  workflow ids, with **+ Workflow** as the fallback when nothing matches.
- **`needs_attention` is surfaced**, so a completed-with-warnings workflow no
  longer reads as a clean "completed".

## Working inside a workflow

Selecting a workflow switches the canvas to a wide conversation lane: summary
tiles (cost / tokens / time / files / build), the live agent graph, the
artifact preview of the deployed app, the generated-files list, and the prompt
threads with their composer. New workflows started from inside the project are
stamped as the project's own and appear in its list immediately.

## Managing a project

Rename or delete a project from its actions menu (delete cascades its
workflows), and jump straight to the GitHub repository from the command bar —
the repo link is backfilled from the first push, so it appears for
auto-provisioned projects too.
