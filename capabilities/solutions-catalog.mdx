title: Solutions Catalog & Template-Last Bootstrapping
description: New projects no longer break when a feature needs something the starter
  template doesn't ship. The template used to be scaffolded before the features were
  known — so a later "add a database" bolted on and quietly failed.
---

## What it enables

**Template-last discovery.** The first build decides design → features →
solutions → intent, and only then the template — the last decision before any
real work, and *capability-driven*: the starter must already ship the stack
your confirmed features need. When no starter fully covers it, the build
**pauses and asks** rather than scaffolding something partial.

**A catalog of solutions.** Common features — waitlist, auth, contact form,
payments, blog — each carry a recipe: what the template must provide, what
to watch out for, and concrete acceptance checks that run before the build
is accepted — so "is the database set up? did the schema land?" is verified,
not assumed, and anything no recipe covers is named back, not dropped.

## What you'll notice

- **First build only.** All of this runs on the first (scaffolding) prompt;
  follow-ups inherit the decisions already made and never re-ask them.
- **It interrupts only when it must.** Confirmation is requested when the
  request was vague or no starter covers the features; otherwise it proceeds.
- **Self-hosted by default.** Recipes point at your own database and
  persistence, never third-party form or data services (Stripe is the
  bounded payments exception).
