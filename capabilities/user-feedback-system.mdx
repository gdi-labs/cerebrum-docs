---
title: Universal User-Feedback System
description: One first-class way for any run to pause and ask you a question — a list
  of options, a free-form reply, or both — instead of silently guessing.
---

## What it gives you

- **One panel for every question.** Single-select buttons, multi-select
  checkboxes, an optional or required text box, or a combination — all
  rendered and answered the same way, wherever the question appears (in the
  timeline, in the task modal, in the pre-run confirmations).
- **Options you can see.** A design or theme choice shows its actual color
  swatches and preview; a template choice shows a design screenshot. An option
  the model recommends is pre-selected.
- **Interrupted only when it matters.** When a pre-run choice (like the
  template) is confident, Amos auto-picks and never interrupts you; when it
  isn't, the run parks and asks — then resumes exactly where it stopped.
- **Answers that steer the run.** Your pick is folded back into the run — a
  chosen template pins the scaffold, a disambiguation routes the work to the
  right flow, a note rides along with the choice.

## Where you'll meet it

- **Pre-run confirmations** — intent, template, design, and the feature list.
  Low-confidence picks pause for your confirmation; confident ones proceed.
- **Mid-run clarifications** — a scope question or an "which did you mean?"
  from any step, answerable from the run panel.
- **Approvals** — the approve/reject shape is the same contract; decided
  approvals can also land from Slack or the approvals page
  (see [Scenario execution](/how-it-works/scenario-execution)).

Because every question is data rather than bespoke UI, a new kind of question
(option picks, multi-selects, clarifications) needs no new interface — it
appears in the same panel automatically.

## Under the hood

The question/answer contract and its event shape are documented in
