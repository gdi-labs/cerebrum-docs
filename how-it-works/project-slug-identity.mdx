---
title: Project Identity — Display Name vs Slug
description: 'Every Amos project carries two identifiers: the name you see, and the
  slug that identifies it everywhere else.'
---

## What it enables

- **Project names are display-only.** Spaces, mixed case and accents are all fine. You type
  "My new landing page" and that string is what shows up everywhere user-facing.
- **Each project has its own stable identity.** Behind the scenes every project gets a
  collision-free internal identifier — its *slug*, built from the name with `-2`, `-3`, …
  appended when the name is already taken. The slug drives the project's GitHub repo, its
  deployment and its stable production URL, and never changes afterward.
- **Same name, separate projects.** Previously, two users each creating a project named
  "test" ended up with one shared project — one repo, one production URL. Now each creation
  gets its own independent project, repo and URL.
- **The workflows list shows real names.** Two "test" projects both read "test", each
  pointing at its own work.

## How it works

1. You type a free-text name (1–80 characters; nearly anything readable is accepted).
2. Amos derives a slug — lowercased, safe for use as a repository name and directory — and
   makes it unique with a `-2`, `-3`, … suffix if needed.
3. That slug drives every external resource the project gets: its GitHub repository, its
   deployment project and production URL, and its working directory.

Older projects keep working: their slug was derived from their existing name, so nothing was
renamed and no repo or URL changed.

## Sharing a workspace

Two people who should work in the same project pick the same existing project from the list
rather than typing the same name — identical names intentionally produce separate projects.
